🧠 Phần 1: AI-Driven Development là gì?

AI-Driven Development ≠ ChatGPT hỏi đáp

🤖 AI-Driven Development là gì?

Không phải "dùng ChatGPT hỏi đáp" — mà là một phương pháp phát triển phần mềm mới

AI-Driven Development = Phương pháp phát triển phần mềm trong đó AI tham gia xuyên suốt mọi giai đoạn (phân tích → thiết kế → code → test → review), với developer giữ vai trò người ra quyết định và kiểm soát chất lượng.

Intent over Syntax

Mô tả muốn gì → AI chuyển thành code

Generate → Review → Iterate

AI generate → Dev review → Feedback → Repeat

Context is Everything

Nhiều context = output chính xác hơn

❌ AI-Driven Development KHÔNG PHẢI
  • ▸ Copy-paste từ ChatGPT vào project
  • ▸ Để AI viết mọi thứ rồi ship không review
  • ▸ Thay thế developer bằng AI
  • ▸ Chỉ dùng AI khi "không biết viết gì"
✅ AI-Driven Development ĐÚNG LÀ
  • ▸ AI tham gia từ đầu đến cuối như team member
  • ▸ Dev điều phối, AI thực thi, Dev verify
  • ▸ Nâng cấp developer thành AI-native developer
  • ▸ Dùng AI có hệ thống: workflow + rules + context

🎯 Phần 2: Khi nào nên / không nên dùng AI

Dùng đúng chỗ = nhanh gấp 3x. Dùng sai chỗ = chậm hơn!

✅ AI mạnh nhất khi...

Những loại task mà AI xử lý nhanh hơn con người rõ rệt

Boilerplate

CRUD, DTO, schema, validation — ~30 phút → vài phút (ước lượng)

Refactor

Rename xuyên file, split function, convert patterns

Explain codebase

Đọc 2000 dòng → tóm tắt flow trong 30 giây

Documentation

API docs, migration guides, README từ code

Unit tests

10-15 test cases trong 2 phút, cover edge cases

Debug (stack trace rõ)

Paste error → root cause + fix trong vài giây

❌ AI yếu khi...

Những loại task mà AI thường fail hoặc chậm hơn code tay

Business rule phức tạp

15 điều kiện pricing → AI thường sai nếu thiếu context đầy đủ

Thiếu context project

Không biết convention, infra constraints → output generic

Feature không chia scope

"Build complete payment system" → 100% fail

Complex debugging

Race condition, memory leak → AI thiếu runtime context

Security-critical code

Auth, encryption, permissions — sai 1 chút = breach

Cross-team coordination

API contracts, migration — cần human communication

Quy tắc vàng: "AI càng nhiều context → output càng đúng." Thiếu context = garbage output.

"AI không thiếu intelligence.
AI thiếu context."

✍️ Phần 4: Prompt Engineering cho Developer

Prompt quyết định: ngữ cảnh • ràng buộc • chất lượng • khả năng bảo trì

📐 Prompt hiệu quả = 5 thành phần

Thiếu phần nào → AI tự đoán → output sai

1. Role
2. Context
3. Task
4. Constraints
5. Output
[Role] Senior Node.js engineer, experience with Bull queue. [Context] NestJS + Bull + Redis. Existing: EmailService, NotificationModule. [Task] Create a queue worker that retries failed email sends (max 3 attempts, exponential backoff). [Constraints] Use @Processor decorator. Log each attempt. Dead-letter after 3 fails. [Output] Worker class + module registration only. No test.

Pro tip: Setup Rules file 1 lần → Role + Context + Constraints auto-apply. Mỗi prompt chỉ cần viết Task + Output.

❌ vs ✅ Bad Prompt vs Good Prompt

Cùng 1 task — kết quả hoàn toàn khác

❌ Prompt xấu
"Viết API upload file"

AI đoán sai: framework, storage, validation, pattern → rewrite từ đầu

✅ Prompt tốt
[Role] Senior Node.js engineer [Context] NestJS, S3, PostgreSQL [Task] POST /api/files, max 10MB [Constraints] Validate mimetype, S3 storage [Output] DTO + Service + Controller

AI output đúng stack, đúng pattern → dùng ngay

Rule: 2 phút viết prompt kỹ = tiết kiệm 30 phút rewrite. Scope nhỏ + Context cụ thể + Iterate = output tốt.

⚖️ vs ✅ Ví dụ Prompt thực tế

Cùng 1 task — prompt xấu vs prompt tốt cho kết quả hoàn toàn khác

Ví dụ 1: API Upload File

❌ Prompt xấu
"Viết API upload file"

AI sẽ đoán:

  • Framework? → Express (mặc định) — nhưng project dùng NestJS
  • Storage? → Local disk — nhưng team dùng S3
  • Validation? → Không có — AI skip luôn
  • Pattern? → Viết hết vào 1 file controller

→ Output không dùng được, phải viết lại từ đầu.

✅ Prompt tốt
[Role] Senior Node.js backend engineer. [Context] NestJS, TypeORM, AWS S3 SDK v3, PostgreSQL. [Task] Create file upload API (POST /api/files). [Constraints] - Max 10MB, allow: jpg, png, webp, pdf - Store file on S3, metadata to FileEntity - Validate mimetype (not just extension) - Follow existing service/controller pattern - Return { id, url, size, mimeType, createdAt } [Output] DTO, Service, Controller. No test yet.

→ Output đúng stack, đúng pattern, dùng được ngay.

Ví dụ 2: Fix Bug

❌ Prompt xấu
"Login bị lỗi, fix giúp"

Thiếu: Lỗi gì? Ở đâu? Reproduce sao? Log nói gì?

✅ Prompt tốt
Bug: POST /auth/login returns 500 when email has uppercase. Root cause: bcrypt compare fails because email lookup is case-sensitive (findOne where email = 'User@...') but registration lowercases email. Fix in: src/auth/auth.service.ts, method validateUser Constraint: use .toLowerCase() before DB lookup. Don't change the registration flow.
Key takeaway: Prompt xấu = 1 dòng mơ hồ → output vứt đi. Prompt tốt = 5-10 dòng có structure → output dùng ngay. Đầu tư 2 phút viết prompt kỹ = tiết kiệm 30 phút rewrite.

"Context quyết định chất lượng
output của AI."

Rules + Skills + MCP + Intelligence = AI hiểu project như senior dev

🚦 Level 3 — Gates quan trọng

Những điểm "dừng lại kiểm tra" bắt buộc — vi phạm = bug production

GATE 1: Test trước Code

AI generate test cases TRƯỚC khi viết implementation. Dev approve test strategy → rồi mới code.

Tại sao? Test-first = AI hiểu rõ expected behavior → code đúng ngay. Code-first = AI đoán.

GATE 2: Verify = Evidence

Không "done" khi chưa có bằng chứng: build pass, tests green, no lint errors.

Tại sao? AI có thể tự tin nói "done" nhưng code chưa compile. Paste evidence = truth.

GATE 3: Spec = Source of Truth

Dev approve spec trước khi AI bắt đầu code. Spec sai → code sai → phải làm lại.

Tại sao? 5 phút review spec tiết kiệm 2 giờ refactor code sai hướng.

GATE 4: Review = Không autopilot

AI output luôn qua human review. Accept/reject từng hunk. Không bao giờ "Accept All" mù.

Tại sao? AI miss security, N+1 query, race condition — human catch những lỗi này.

🚦 Level 4 — Gates quan trọng

4 gates bắt buộc — mỗi phase phải deployable + rollback-able independently

GATE 1: Test Design trước Implement

Step 8 phải hoàn thành và được approve trước khi Step 9. AI generate test strategy (unit/integration/E2E/security/contract).

Tại sao? Hệ thống lớn không có test strategy = ship bug ẩn cross-service.

GATE 2: Discover = Blast radius bắt buộc

Step 4 — AI phân tích tất cả service bị ảnh hưởng, dependency graph, integration points trước khi Spec.

Tại sao? Cross-service change thiếu blast radius = break service khác mà không biết.

GATE 3: Human review liên tục

Không autopilot ở L4. Dev review từng PR per phase. Team/lead/security approve ở Step 12 trước Ship.

Tại sao? AI generate code cho 1 service — không hiểu side effects trên service khác.

GATE 4: Phase = Deployable + Rollback

Mỗi phase trong Plan phải deploy được độc lập và có rollback strategy (canary → rollout).

Tại sao? Deploy big-bang 15+ files = risk max. Phased deploy = rollback an toàn.

⚡ Phần 6: Thực tế khi áp dụng AI

Thực tế khi áp dụng AI — sai lầm thường gặp và bài học rút ra từ project thật

💀 7 Sai lầm thường gặp (1–4)

Anti-patterns khiến AI output tệ

1. Prompt quá mơ hồ

AI đoán sai stack, pattern → rewrite từ đầu

Fix: Role + Context + Task + Constraints + Output

2. Task quá lớn

AI mất focus, output fragmentary, thiếu edge cases

Fix: Chia 1 feature → 5-10 prompts nhỏ

3. Copy code không hiểu

Accept All → bug production → không debug được

Fix: Đọc hiểu từng block trước khi accept

4. Trust AI tuyệt đối

AI hallucination: API không tồn tại, logic sai edge case

Fix: "Trust but verify" — luôn chạy test

💀 7 Sai lầm thường gặp (5–7)

3 sai lầm còn lại + tổng kết

5. Không review security

AI thiếu: auth check, pagination, sanitization

Fix: Security checklist mỗi PR

6. Thiếu context codebase

AI dùng style khác nhau mỗi lần generate

Fix: Rules file + @file reference

7. One-shot mindset

Expect 1 prompt = perfect output. Thực tế cần 2-3 rounds.

Fix: Generate → Review → Refine → Done

Pattern chung: Thiếu context + thiếu scope control + thiếu verification = AI output tệ. Fix = Rules + Chia nhỏ + Verify.

IDE được thiết kế từ đầu cho AI — không phải plugin add-on. AI là first-class citizen trong mọi workflow.

  • Cursor — AI-first fork VS Code
  • Kiro — Spec-driven development
  • Windsurf — Cascade context engine
  • Claude Code — Terminal-based agent

Impact: IDE cũ (VS Code thuần) sẽ dần bị thay thế bởi AI-native IDEs.

Autonomous Agents

AI không chỉ generate code — mà tự plan → execute → test → fix → ship theo loop tự động.

  • Agentic Loop — AI tự lặp: plan → code → test → fix cho đến khi pass
  • Multi-agent — nhiều AI phối hợp, mỗi AI 1 vai trò (code, test, review)
  • Background workers — AI chạy async tasks
  • Self-healing — AI tự phát hiện + sửa bug khi code chạy lỗi

Impact: Dev chuyển từ "code" → "review + approve" cho routine tasks.

Deep Codebase Understanding

AI hiểu project như senior developer: history, decisions, patterns, team conventions — không chỉ syntax.

  • Code Graph — dependency + call chain
  • Git History — hiểu evolution of decisions
  • Team Knowledge — learn từ PR reviews
  • Domain Model — hiểu business concepts

Impact: AI output match team style 95%+ — gần như không cần sửa.

Kỹ năng dev cần phát triển (AI không thể thay thế): Architecture thinking • Domain expertise • System design • Security mindset • Code review skill • Prompt engineering • AI workflow orchestration

‍💻 Developer sẽ thay đổi như nào?

Vai trò developer đang shift — từ "người viết code" sang "người thiết kế + điều phối"

👨‍💻 Traditional Developer
  • ▸ Viết code từ đầu đến cuối
  • ▸ Nhớ syntax, API, patterns bằng đầu
  • ▸ Debug bằng print/log thủ công
  • ▸ Search Google/StackOverflow cho mỗi vấn đề
  • ▸ Tự viết tests, docs, boilerplate
  • ▸ Giá trị = số dòng code viết được / ngày
🎯 AI-Era Developer
  • ▸ Design systems — kiến trúc, contracts, boundaries
  • ▸ Orchestrate AI — prompt, rules, workflow design
  • ▸ Validate architecture — review AI output vs business needs
  • ▸ Review & approve — security, performance, correctness
  • ▸ Define constraints — rules, conventions, quality gates
  • ▸ Giá trị = quality of decisions / ngày

Key message: Developer không bị thay thế — developer được nâng cấp. Kỹ năng quan trọng nhất sẽ là: architecture thinking, domain expertise, AI orchestration. Code sẽ trở thành commodity — decisions mới là giá trị.
